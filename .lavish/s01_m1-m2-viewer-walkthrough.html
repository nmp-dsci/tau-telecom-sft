02 · architecture

Four lanes on one Mac, and two ledgers that read them

Each box is a module or a folder. Solid arrows are the data's path; the green path is a student's turn being served. Every box writes something the next one reads, and nothing reads MLflow back.

What runs where

  • This repo, the Mac: the build, the trainer (PyTorch on MPS), MLX serving, the proxy, the scorer and the viewer.
  • tau2-loop: its worktree ../tau2-loop-student on branch feat/open-student. Your main checkout is untouched.
  • nmp-central-ai: MLflow on :5000. Nothing else was started.
  • Ports: 8020 proxy, 8120 MLX, 8085 viewer, 5177 dev UI. 8000 belongs to another app on this Mac.

The same code goes to EC2 at M3 and M4

  • train/sft.py runs configs/sft_a.yaml on CUDA unchanged. Liger switches on and the Mac's block attention switches off.
  • serve/proxy.py stays on the Mac in front of the port forward to vLLM. The prompt-bytes check works the same way.
  • tau2-loop's s versions point at whatever STUDENT_URL names.
  • One new thing at M3: serve/vllm.py and the student entries for the 4B.

04 · the fine-tuning code

One config, one trainer, one mask check, and the callback that records every step

Excerpts from the committed files, shown as they are. The trainer is plain TRL and PEFT. What this repo adds: the check that the loss lands where it should, the run folder, and the Mac's memory fix.

configs/smoke.yaml lines 1–41

The whole config. Every key under sft: is TRL's SFTConfig under its real name. configs/sft_a.yaml, M4's 4B run, has the same shape: 3 epochs, 24,576 tokens, Liger on.

src/tau_telecom_sft/train/sft.py lines 166–210

The trainer. Load the base, build the dataset (tools as a JSON string, so Arrow never merges their schemas), hand TRL a LoRA config, then read the trainer's own labels for row 0 and check them before step 1.

src/tau_telecom_sft/train/mask.py lines 57–91

The check: one trained span per agent turn, each holding that turn's text and calls and ending with <|im_end|>, and no context text inside a trained span

src/tau_telecom_sft/train/callbacks.py lines 43–79

Every logged step goes to metrics.jsonl first and to MLflow second. A failed MLflow call is noted once and never stops the job. This is the EC2 tunnel question from earlier, answered in code.

src/tau_telecom_sft/train/attention.py lines 35–65

The Mac's memory fix: SDPA on 1,024 queries at a time, against only the keys each may see, each block recomputed in the backward pass. The smoke config alone selects it.

tau2-loop: src/tau2_loop/agent/factory.py lines 83–96

tau2-loop's side (D5): a student's route, which is its endpoint, its sampling and native tools, with no effort, service or key. The customer and the judge never take this route.

05 · how you see fine-tuning performance

Three questions, each with its own screen

1 · Did training behave?

The loss per step, learning rate, gradient norm, tokens per second and memory.

  • Viewer: /train/20261017T120150Z_train_smoke-0.6b; ?vs= overlays another run
  • MLflow: tau-telecom-sft/train, run b52a4b02: the same steps plus CPU, memory and, on EC2, GPU system metrics
  • File: runs/20261017T120150Z_train_smoke-0.6b/metrics.jsonl

2 · What did it learn from?

Exactly which tokens carried the loss, on a real row.

  • Viewer: any row's ?lens=tokens, and the run's mask check on /train/:run
  • CLI: make mask prints it
  • File: runs/<id>/mask.json

3 · Did it help?

pass^k on tau2's grader, and fixed and broken tasks against the untrained base, with the sign test.

  • Viewer: /eval/:run?vs=, the task × trial grid, every conversation
  • MLflow: tau-telecom-sft/eval and tau2-loop's own runs
  • File: runs/<eval>/run.json

The smoke run's loss, read from metrics.jsonl

16 steps, one row each, read from runs/20261017T120150Z_train_smoke-0.6b/metrics.jsonl. Loss 1.469 at step 1 and 0.872 at step 16. The learning rate warmed up to 2e-4 at step 2, then fell on a cosine. Each step is a different conversation, so the curve is noisy. Its trend is what matters, and it falls.

How to read these numbers. All 74 training tasks are trained on (D1), so no held-out loss exists. The training loss shows the job behaved, and only tau2's grader on the 40 test tasks measures the student (M5). The smoke run is 16 rows for one epoch on a 0.6B model, and its 3 scored tasks are training tasks. It proves the plumbing, not the method.

07 · what the data said

Eleven things the build found that the plan could only guess

The board data

  • 518 kept, the top of the plan's 430–520 guess. S2 (Qwen3.5-397B) gave 273 and S1 (GLM-5) 245. By symptom: MMS 212, data 165, service 141.
  • F4 dropped 7 passes that called the customer's phone tools, such as check_apn_settings and grant_app_permission. Telecom's trap, in the teachers' own data.
  • GLM-5 ran at temperature 0.0 according to its own file, not the 1.0 its submission notes say. Qwen3.5 ran at 1.0 with top_p 0.95.
  • 52 GLM-5 conversations were infrastructure errors with no reward. F1 dropped them.
  • 1,204 teacher turns hold text and a tool call together, though the stock prompt asks for one or the other. They're kept as tau2 stored them, so the student learns to narrate before a call.
  • Shorter than feared: median 10,054 tokens and max 16,869, against the 15K and 26K estimated from Haiku's runs. The L4 only has to fit 17K.

The pipeline

  • The trained text includes the newline after <|im_end|>, because TRL's training template puts it inside the generation block. The plan's §6 said the turn ends at <|im_end|>. It's harmless, but now you know.
  • The untrained 0.6B calls phone tools it doesn't have. In the measured conversation it called check_apn_settings and then run_speed_test and check_speed. tau2 ended it for too many errors after 21 turns. That's exactly what F4 keeps out of the training rows.
  • The policy in the board files matches the pin's policy byte for byte, so rebuilding the prompt at the pin is exact.
  • 16 rows moved one behaviour, not the score. The untrained 0.6B named its own tools in 36.6% of its calls (24 calls went to phone tools, 2 to tools that exist nowhere). After 16 rows it did in 94.5% (6 phone, 0 invented). But it then looped: get_details_by_id 74 times, and one conversation hit tau2's 200-step cap. Both models passed 0 of 3.
  • Mac speed: about 75–130 tokens a second training the 0.6B at 10K tokens, and 5–15 s per served agent turn. That's fine for plumbing and nothing more, which is why M3 onwards uses the L4.
